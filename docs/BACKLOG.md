### FFX-B01 — PyInstaller spec hard-codes a non-existent `.ico`, build aborts
- **Severity:** CRITICAL
- **Location:** `packaging/FFExplorer.spec:111` (also `:110` comment; `packaging/build.py:54-70` `ensure_ico`; `png_to_ico.py:38-46`; `pyproject.toml` `dev` group)
- **Root cause:** `icon=str(Path(REPO_ROOT) / 'Logo FFE.ico')` is set unconditionally, but the `.ico` is not in the repo and is only generated by `ensure_ico()` which needs Pillow — Pillow is in no dependency group. If Pillow is absent, `ensure_ico` returns `False` but the spec still references the path, so PyInstaller raises `FileNotFoundError` and the build fails out-of-the-box.
- **Fix approach:** Guard the icon: `icon=str(ico) if Path(ico).exists() else None`. Add `Pillow` to a `build` (or `dev`) extra in `pyproject.toml` so `ensure_ico` can succeed. Ensure `build.py` runs `ensure_ico` before invoking PyInstaller and degrades gracefully (build with no icon) when generation is impossible.
- **Acceptance criterion:** On a clean checkout with no `Logo FFE.ico` present, `python packaging/build.py` completes and produces an executable (with or without the icon) and exits 0; with Pillow installed, the `.ico` is generated and embedded. No `FileNotFoundError`.
- **Asset capability needed:** edit PyInstaller `.spec` + `build.py`, and edit `pyproject.toml` dependency groups.

### FFX-B04 — Packaging hidden-imports/excludes are Windows-skewed despite "cross-platform" claim; UPX risks corrupting Qt binaries
- **Severity:** MEDIUM
- **Location:** `packaging/FFExplorer.spec:64-65` (hiddenimports `send2trash`, `send2trash.win`), `:103,119` (`upx=True`), `:11` (cross-platform header)
- **Root cause:** `send2trash.win` is the Windows-only backend; POSIX needs `send2trash.plat_other` (and `.mac`), which are not declared. `upx=True` frequently corrupts PySide6 `.so`/`.dylib` bundles and is discouraged for Qt.
- **Fix approach:** Make hidden imports OS-conditional (`sys.platform`): add `send2trash.plat_other` / `send2trash.mac` on POSIX/macOS. Set `upx=False` for the Qt bundle (or gate UPX off when bundling PySide6).
- **Acceptance criterion:** The spec declares the correct `send2trash` backend per platform (verifiable by inspecting the conditional block); `upx=False` in effect for the Qt build; a Linux/macOS build (or a static assertion in `build.py`/a test) confirms the POSIX backend is included.
- **Asset capability needed:** edit PyInstaller `.spec` (OS-conditional hiddenimports + UPX flag).

### FFX-I01 — Regex matching mode alongside substring/glob seed
- **Value/Effort:** High / S
- **What it adds:** A `match_mode` (`substring` | `glob` | `regex`) on the query so `regex:`-style power matching joins the current case-sensitive `in` test; document that operators don't combine with regex mode.
- **Why it matters:** The review/understanding flagged search semantics as weak (R-4: case-sensitive substring only). Regex is the single highest-leverage, lowest-cost search upgrade and maps directly onto an MCP/REST parameter.
- **Reference tool:** voidtools Everything — Regex matching mode. (research §2, https://www.voidtools.com/support/everything/searching/)
- **Modules/files touched:** `ff_explorer/core.py` (`list_entries`/filter), `ff_explorer/api/service.py` + `rest.py` (new `match_mode` field), `ff_explorer/gui/main_window.py` (mode selector), `tests/test_core.py`.
- **Approach:** Add a `match_mode` parameter to the pure query; compile a `re.Pattern` once when `regex`, translate glob via `fnmatch.translate` when `glob`, keep `in` for `substring`. Add a case-insensitive flag while here. Surface as a Pydantic field (default `substring`) and a GUI combobox.
- **Acceptance criteria:** Querying a known tree with `regex:^foo.*\.txt$` returns exactly the regex-matching entries; invalid regex returns a 422 (REST) / clear error; substring behavior is unchanged when mode is default. Tested at core + REST.
- **Asset capability needed:** edit core query engine + add a new query parameter to the MCP tool + REST route + GUI control + add pytest cases.

### FFX-I10 — Real-time live name indexing
- **Value/Effort:** Low / L
- **What it adds:** An in-memory name index plus filesystem-change monitoring so results update instantly instead of re-walking the tree per query.
- **Why it matters:** The headline Everything capability; biggest perceived speed win, but the largest build (index lifecycle + watcher) and lowest priority for a small training app — schedule last.
- **Reference tool:** voidtools Everything — real-time live indexing. (research §1, https://www.voidtools.com/support/everything/using_everything/)
