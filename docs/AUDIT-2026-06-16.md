## P1 — correctness / forward-compatibility

### A-01 — Starlette `HTTP_422_UNPROCESSABLE_ENTITY` is deprecated
- **Where:** `ff_explorer/api/rest.py:777` and `:784`.
- **Symptom:** Emits `DeprecationWarning: 'HTTP_422_UNPROCESSABLE_ENTITY' is deprecated. Use
  'HTTP_422_UNPROCESSABLE_CONTENT' instead.` (visible in the test run). It is one of the 18
  warnings the suite currently raises.
- **Why it matters:** When Starlette removes the alias, the import-time `status.HTTP_422_…`
  reference raises `AttributeError` and the access layer fails to import — a hard break, not
  cosmetic, on a future dependency bump (the `<1` ceilings do not pin Starlette).
- **Fix:** Define the constant `422` locally (e.g. `HTTP_422 = 422`) or branch on availability:
  `getattr(status, "HTTP_422_UNPROCESSABLE_CONTENT", status.HTTP_422_UNPROCESSABLE_ENTITY)`.
  Owner: access-dev. Re-run the gate; warning count should drop.

### A-02 — `QMouseEvent` deprecated constructor in GUI tests
- **Where:** `tests/test_gui_smoke.py:344` and `:361`.
- **Symptom:** `DeprecationWarning: QMouseEvent(...)` (the multi-arg constructor is deprecated in
  this PySide6).
- **Why it matters:** Same forward-compat risk as A-01 but test-only; will turn into a hard error
  under `-W error` or a future PySide6.
- **Fix:** Use the supported `QMouseEvent` constructor / `QTest.mouseClick` instead. Owner:
  test-author or gui-dev.
